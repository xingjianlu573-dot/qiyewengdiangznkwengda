# 网络故障处理 SOP（标准作业流程）

> 适用范围：公司全体员工 / IT 运维一线。目标：15 分钟内完成初步定位，30 分钟内给出处理方案或升级路径。

## 一、故障分级与响应时限

| 级别 | 影响范围 | 响应时限 | 处理人 |
| --- | --- | --- | --- |
| P1 严重 | 全公司断网 / 核心业务不可用 | 10 分钟 | 网络工程师 |
| P2 重要 | 单部门或多楼层网络异常 | 30 分钟 | 运维工程师 |
| P3 一般 | 单台电脑无法上网 | 4 小时 | 桌面运维 |

## 二、第一步：快速定位（2 分钟）

1. 询问员工故障现象：是完全无法上网，还是部分网站打不开、网速慢、时断时续。
2. 查看任务栏网络图标：黄色感叹号 / 红叉 / 正常，分别对应不同方向。
3. 执行三条基础命令（以管理员身份打开命令提示符）：
   - `ipconfig` —— 查看 IP 地址是否为 169.254.x.x（自动获取失败）或 0.0.0.0；
   - `ping 网关地址` —— 通不通决定是内网链路问题还是外网问题；
   - `ping 8.8.8.8` 与 `ping www.baidu.com` —— 对比判断是 DNS 问题还是路由问题。

## 三、第二步：逐层排查流程

按「物理层 → 链路层 → 网络层 → 传输层 → 应用层」顺序排查，不要跳层。

### 3.1 物理连接检查

- 网线两端是否松动，水晶头卡扣是否损坏；交换机 / 面板指示灯是否常亮；
- 无线用户：确认 Wi-Fi 已连接，信号强度是否过低（< 两格建议靠 AP 或改用有线）；
- 检查电脑网卡是否被禁用（设备管理器 → 网络适配器）。

### 3.2 IP 地址与 DHCP

- `ipconfig /release` 后执行 `ipconfig /renew` 重新获取地址；
- 若拿到 169.254 地址：检查 DHCP 服务是否正常、网段是否耗尽、网卡驱动是否异常；
- IP 地址冲突（弹窗提示“网络上已有重复的 IP 地址”）：换一台电脑排查或使用 `arp -a` 定位冲突设备。

### 3.3 网关与路由

- `ping 网关` 不通：检查接入交换机端口、网线、VLAN 配置；
- `ping 网关` 通但 `ping 8.8.8.8` 不通：问题在出口路由 / 防火墙 / 运营商链路；
- 内网互访正常但外网异常：重点检查出口防火墙策略与运营商线路状态。

### 3.4 DNS 解析

- `nslookup www.baidu.com` 无法解析：检查 DNS 服务器配置（建议 114.114.114.114 / 223.5.5.5 或公司内部 DNS）；
- 能解析但不能访问：可能是代理设置异常或 hosts 文件被篡改（检查 C:\Windows\System32\drivers\etc\hosts）。

### 3.5 代理 / 防火墙 / 安全软件

- 检查系统代理设置（设置 → 网络和 Internet → 代理）是否被异常开启；
- 临时退出安全软件 / 防火墙测试，确认是否为拦截导致；
- 浏览器无法访问但 ping 正常：多为代理或浏览器插件问题。

## 四、常见错误码速查

| 现象 | 原因方向 | 处理 |
| --- | --- | --- |
| 169.254.x.x | DHCP 获取失败 | 检查 DHCP 服务 / 网线 / 交换机端口 |
| 无法访问默认网关 | 网关或链路异常 | 查交换机端口与 VLAN |
| DNS 解析失败 | DNS 服务器不可达 | 更换 DNS，检查 DNS 服务 |
| IP 地址冲突 | 网段内有重复 IP | arp -a 定位并处理 |
| 无法 ping 通任何地址 | 网卡禁用 / 驱动异常 | 启用网卡、重装驱动 |

## 五、无线网络故障专项

1. 忘记并重新连接 Wi-Fi（删除配置文件后重新输入密码）；
2. 重启无线网卡：禁用后重新启用；
3. 若多台设备同时掉线：重启无线控制器 / AP，检查 AC 与 AP 版本；
4. 信号弱但位置固定：登记 AP 点位，安排现场勘测。

## 六、网络恢复验证清单

- [ ] ping 网关通，无丢包；
- [ ] ping 8.8.8.8 通；
- [ ] nslookup 域名解析正常；
- [ ] 浏览器可正常访问公司 OA / 业务系统；
- [ ] 内网共享与打印机可用。
