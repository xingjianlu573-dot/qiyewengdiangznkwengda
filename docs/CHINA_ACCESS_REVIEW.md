# 中国大陆访问风险审查报告

> 审查对象：Enterprise Document Intelligence Assistant（当前 GitHub 版本）
> 审查日期：2026-10-05　|　审查视角：中国大陆普通用户（无特殊网络环境）

---

## 一、审查结论摘要

**总体判断：项目架构本身已高度"国内友好"** —— 前端零 CDN、零 npm、零第三方 JS；后端无国外数据库/对象存储依赖；AI 接口全部可配置且默认离线可跑。主要风险集中在**部署链路**（Docker 镜像源、pip 源、GitHub 访问）与**国产模型一键接入**的缺失，均为"可低成本解决"的工程问题，不涉及架构重构。

| 维度 | 风险等级 | 说明 |
| --- | --- | --- |
| 前端资源 | 🟢 无风险 | 全部静态资源本地化，无 CDN / npm / 第三方 JS |
| 后端服务 | 🟢 无风险 | 同源部署，无跨域、无外部依赖 |
| AI 服务 | 🟡 中风险 | 无硬依赖国外 API，但缺国产模型一键切换 |
| 部署链路 | 🔴 高风险 | Docker Hub / PyPI / GitHub 在国内访问慢或不稳定 |

## 三、风险分级处理清单

### 🔴 高风险（必须处理）
1. **Docker 镜像拉取** → Dockerfile 内置清华 pip 源；README_CN 提供 daemon.json 国内加速器配置（阿里云/腾讯云）与国内镜像仓库替代方案。
2. **GitHub 访问链路** → README_CN 提供 Gitee（码云）镜像仓库同步步骤，作为国内用户的下载/克隆通道。

### 🟡 中风险（本次一并处理）
3. **国产模型一键切换** → 新增 `MODEL_PROVIDER` 环境变量，内置通义千问 / 智谱AI / DeepSeek / 月之暗面 / SiliconFlow / OpenAI 的默认网关地址与模型名。
4. **国内部署文档缺失** → 新增 README_CN.md（国内服务器方案 A / 云平台方案 B / 本地 Docker 方案 C）。

### 🟢 无风险（确认保持）
5. 前端本地化、同源架构、离线双模式、零向量库依赖 —— 保持现状即可。

## 四、优化方案（低本高效，适合作品展示）

1. **AI Provider 抽象层**：`MODEL_PROVIDER=qwen|zhipu|deepseek|moonshot|siliconflow|openai|offline`，环境变量一键切换，不破坏现有功能；
2. **Docker 优化**：pip 清华源 + 镜像加速文档 + 构建缓存优化；
3. **数据本地化**：已完全本地化，无需处理；
4. **部署方案**：A 国内云服务器（阿里云/腾讯云轻量）· B 国内云平台（宝塔/函数计算）· C 本地 Docker；
5. **国内下载通道**：Gitee 镜像仓库同步指南。
